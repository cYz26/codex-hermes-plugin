# 自动学习：从追加要求提炼方法

Codex 接入层把同一聊天的初始目标、原先做法、用户追加要求和后续结果组织为有来源的复盘输入。Hermes 继续负责多轮复盘、Memory／Skills 写入和原生审核；自然表达的追加要求会进入改进候选，由复盘判断是否体现方法变化。用户无需额外说“记住”。

## 证据与预算

原生 observation 已经累计同一 handle 的多轮记录。接入层按 intent 的 revision 截止点只读原生 journal，为请求、结论和工具交换标注证据引用，去除重复的补充请求／相同结论，并保留 observation 与来源回合的对应关系。用户请求时间优先来自已验证宿主记录；缺少时间时注明采集或 journal 到达顺序。迟到结论保留自己的 revision，不能被标成早先追加要求的前一结论。

复盘副本仍受 64 KiB 和原生总预算约束。先压缩媒体、重复及冗长工具输出，再保护目标、追加要求、相关前文和后续结论。较早结论裁剪时优先保留与相邻请求相关的原文片段。遗漏组范围、裁剪引用和未配对工具交换写入覆盖记录；片段不代表保存了完整历史。

工具交换必须按实际调用 ID 和结果 ID 配对。缺失、重复或不匹配的交换作为未验证执行证据呈现，不向模型重放一个错误配对的函数调用。原生异模型复盘仍采用其尾部选择；接入层保留已受预算约束的对话主线，并进一步限制该 fork 能引用的实际输入。

## sidechat 关联

宿主 0.167 的 `session_meta` 提供 `forked_from_id`、`forked_from_ordinal_exclusive`、`history_base` 和 `attached_thread`。接入层核对宿主文件位置、所有者、聊天身份、工作区和字段一致性，再记录父聊天与分叉位置。字段缺失或冲突会显示明确缺口。

父上下文仅取同一宿主和项目下已经保留、当前仍获准的父回合，并按真实分叉 ordinal 排除后续请求、结论和工具。宿主读取只补充关联、消息位置和终态元数据。父任务正文不从 transcript 导入，也不作为新的子任务 observation 计数。较早正文未保留时继续记录该缺口。父材料用于理解子任务新增信息，写入必须有子任务自身的证据。

响应选中文本和评论来自已准入的用户请求，保留源消息 ID／偏移与截断说明。只有宿主消息元数据和已保留正文能够对应时才标注已关联回合；无法核对的引用保持未解析状态。独立聊天不会因 cwd 相同而成为父任务。

## 归类与写入

复盘先选择当前任务相关的可读技能，再使用原生工具创建或修订 `learned-<topic>`。已有技能需在本次复盘重新读取。没有适当旧技能时可以创建通用流程候选，之后按现有来源、资源和发布检查处理。

每项写入附带桥接层检查的证据声明：

```json
{
  "classification": "procedure",
  "basis": [
    {"ref": "T1.result", "quote": "此前方法的原文片段"},
    {"ref": "T2.request", "quote": "用户追加要求的原文片段"},
    {"ref": "T2.result", "quote": "后续结果的原文片段"}
  ],
  "rationale": "说明方法变化、适用范围以及该技能为何适合承载此修改。"
}
```

引用须匹配实际送入 fork 的原文；类型为项目事实、通用流程或稳定偏好。项目事实留在项目 Memory，通用流程进入适当技能；稳定偏好的用户引用片段本身需表明持续适用范围，不能借用同一请求中无关的长期措辞。父上下文、助手自己提出的偏好、伪造引用不能独立授权写入。显式资料学习可以直接引用已准入 material，其内容不构成执行验证。

相关性与引用检查在写入前运行，证据声明从操作中移除后交给原生工具。新的版本化语义技能凭证包含任务证据检查结果，发布仍执行原来的资源／内容和独立脚本验证。Markdown 章节完整、已发布、已加载以及真实任务中有效分别记录。相关性筛选保守，语义判断继续由原生复盘完成；最终业务有效性需要实际应用证据。

## 消费与进度

事件箱持续持久采集。worker 按时间与数量上限消费多个事件页，长复盘每次最多执行一项后返回消费；仍有积压时先给消费阶段机会，并保留复盘的有界公平机会。缺失输入重试按上次尝试顺序轮转和退避，避免最新八条记录反复占满恢复队列。迟到的同回合请求回执保留已收到的 Stop／Interrupt。

原生 idle flush 可能因旧 revision 已排队而暂缓新 intent。接入层核对 intent 实际覆盖到反馈的 revision 后才标记请求完成，旧复盘也不能清除较新回合的优先级。旧 intent 结束后，尚未覆盖的反馈继续请求复盘。

已有 30 天回合留存流程同时清理相应的宿主游标、复盘输入、候选引用与进度。技能版本凭证保留检查状态和摘要哈希，过期来源原文不作为永久复盘副本保存。

追加要求和用户纠正可以根据真实 Stop 的对话结果复盘，同时保留未解决的工具状态与缺口。工具恢复信号仍要求相同测试和真实终态；对话学习不会据此声称工具已经正确执行。

```sh
scripts/bridge status --settings /ABS/bridge.json --cwd /ABS/workspace --chat CHAT_ID --turn TURN_ID
```

MCP `learning_status` 同样接受 `cwd`、`chat`、`turn`、`limit` 和 `after_cursor`。`progress` 分别返回：

- 采集与消费数量、按回合计算的积压时长，以及最后采集／消费位置；
- 准入或拒收原因、正文覆盖和缺失输入重试；
- 原生 revision、复盘 intent、复盘状态及是否包括本回合；
- 实际候选声明、原生写入／暂存数量、候选和发布版本；
- 召回推荐、hook 实际提供的技能名、宿主确认的正文交付、应用声明及已有宿主测试验证；
- 父上下文和复盘预算的覆盖缺口、worker 阶段与队列快照年龄。

Hook 在 256 UTF-8 字节内优先放入至多三个完整技能名。召回按当前项目和发布范围筛选，再补充直接相关技能的双向关联。`offered_skills` 记录该回合由 hook 提供的技能名。`offered_versions` 给出当时可读取的正文版本，旧回合可能缺少该字段。按项目和聊天查状态时，`mcp_recommendations` 列出该回合保留的 MCP 召回记录。`context.skills[].artifact_version` 可传给 `skill_load`，确认读取的是召回时的版本。原生目录指纹仍由 `context.skills[].version` 提供。

应用验证根据宿主保留的命令和终态核对，反馈优先调度关闭时也会工作。识别常用的 Python、包管理器测试入口及本项目的发布检查。旧回合保留了命令时可按同一规则识别。

提交反馈时，向 `feedback_status` 传入 `cwd` 和 `chat`，可选指定 `turn`。把对应的 `test_references[].source_event` 原样放进 `record_application.source_events`。完整诊断 `learning_status` 继续在 `execution.test_references` 返回同样的引用。已采集的测试可以先提交，worker 随后核对终态。保存返回的回执 ID，可用 `feedback_status` 的 `receipt_id` 读取结果。

反馈回执会区分待消费、待宿主终态、找不到引用、引用非测试以及终态无退出码。针对同次交付和同一批回合提交更正后，错误引用的旧回执可以标为 `superseded`，并记录替代回执 ID。已确认的测试结果可追溯至 Hook 退出码、宿主 transcript 或工作流投影。发往原生复盘的状态工具结果保留状态与版本等字段，完整状态仍可通过原入口读取。

`effective_policy` 显示运行中 worker 的准入、共享、质量检查、留存、复盘与 Curator 配置。`memory_capacity` 显示原生记忆文件的用量、配置上限、各项目条目及字符数和待审数量。传入 `cwd` 可读取该项目的明细及最近记录的容量拒绝。`sharing` 根据已保存的发布版本估算开启严格共享后该项目可见的目录数量。

分页游标枚举已采集回合组；查询某回合当前状态应使用其聊天／回合身份。服务 `ready`、`idle` 和旧 snapshot 只说明各自组件状态，进度记录用于判断是否仍有等待阶段。

## 验证入口与边界

`tests/test_evidence.py`、`test_review_input.py`、`test_semantic_review.py` 和 `test_learning_progress.py` 覆盖关联、裁剪、写入和回合进度。`probes/scoped_contract.py` 继续验证原生工具与显式资料分批学习；`probes/feedback_learning.py` 验证自动反馈学习、无关技能保护、跨项目召回和受控计划变化，支持 sidechat 与异模型合同场景。

真实 provider 模式显式传入 `--live-settings`，在独立学习 home 使用合成对话，复用原生 worker 的模型工厂。计划实验把同一个初始公开资料计划分别与召回方法、用户来源限制组合，检查明确计划使用的来源。它验证原生模型产物和受控计划应用；实际内部资料查询、Desktop 跨聊天执行和生产切换仍需相应验收。
