# 自动反馈学习实现与验证

本报告保留 2026-11-11 开发分支的验证范围与当时生产状态。后续合并、发布及升级见 [0.10.0 发布说明](./RELEASE-0.10.0.zh-CN.md)，下列历史结果不重标为新版验收。

用户自然追加要求后，自动学习需要保留原先做法与后续结果，判断是否产生了可复用的方法变化。此次开发分支实现五项改进，复盘仍使用原生 Hermes 的模型、工具和写入流程，用户无需额外说“记住”。

工作分支为 `codex/learning-evidence`，基于 `1b178ab`；包版本保持 `0.8.0`。这是尚未激活的开发代码。生产安装、模型配置、预算和学习数据由既有运行时管理，本次没有执行安装、生产切换、服务重启、推送或合入。原工作区的其他改动保留在原处。

## 五项行为与回归范围

| 改进 | 实现与验收内容 | 主要回归 |
| --- | --- | --- |
| 跨轮证据 | 原生 journal 按 intent revision 截止，串联目标、先前结论、追加要求和后续结果；去重补充消息，保留迟到结论自己的来源 | [证据关联](../tests/test_evidence.py) |
| 保真裁剪 | 先压缩媒体和工具输出，再保护对话主线；原文摘录带裁剪记录，来源标签不参与内容相关性排名；异模型 fork 只可引用实际收到的片段 | [预算与工具配对](../tests/test_review_input.py)、[原生合同](../tests/test_native_scoped_contract.py) |
| sidechat | 核对宿主父聊天及真实分叉位置，只取同项目、已留存且仍获准的父上下文；未留存正文与无法核对的选中文本明确降级 | [宿主合同](../tests/test_host_evidence.py)、[增量游标](../tests/test_incremental.py) |
| 技能归类与相关性 | 区分项目事实、通用流程和用户支持的稳定偏好；写入附原文引用及目标理由，修订前读取技能；稳定范围必须出现在用户引用片段本身 | [语义写入](../tests/test_semantic_review.py) |
| 队列与进度 | 自然追加产生候选；多页有界消费、每轮最多一次长复盘，缺失输入公平退避；按实际 revision 确认反馈覆盖，区分采集、准入、复盘、候选、发布和召回 | [主动触发](../tests/test_proactive.py)、[分阶段进度](../tests/test_learning_progress.py) |

代码复核覆盖所有本次源码修改、新模块、调用方及相关测试。复核发现并修正了来源标签抢占关键摘录、无关长期措辞误授权稳定偏好两处边界问题，新增回归先复现失败、再验证修正。原生的按目标文件读取后再写入检查仍然有效。探针的来源限制检查同时排除了单独出现“explicit requirements”即误报通过的情况。

## 模型产物与计划变化

真实实验使用独立学习 home 和合成任务，复用生产既有的 `custom:ark`／`ark:gpt-6-1-sol` 模型工厂与预算；原生用量中的 provider 名为 `custom`。没有导入生产 Memory、历史任务正文或发布库。

合成输入为：先只比较公开方案，用户自然要求补查内部能力，后续结果报告内部共享服务改变了首选。实际生成的[方法原文](../evidence/automatic-feedback/2026-11-11/learned-method.md)另存为验证材料，包含适用条件、比较步骤、来源缺口和验证限制。

随后在另一合成项目对工作流编排选型进行三次计划实验：

| 条件 | 计划使用的来源 |
| --- | --- |
| 未提供召回方法 | 保留公开资料计划 |
| 提供召回方法 | 纳入获准的内部能力，与公开方案共同比较 |
| 提供召回方法且用户要求仅用公开资料 | 保持公开资料限制，并披露内部覆盖缺口 |

实验还核对了无关 CSV 技能未改动、另一项目未收到项目 Memory、通用技能被推荐及加载。计划中的 `planned` 字段用于判断是否真正计划使用某类来源，避免把“不会查询内部资料”误算成使用内部资料。技能被加载与上述计划变化分别记录。

## 尚未覆盖的范围

尚未运行最终代码的真实 Desktop 跨聊天学习与应用，也没有执行计划中的内部资料查询、业务选型或操作性验证。本次真实模型结果支持受控计划改善，不能据此证明实际业务结果改善。

宿主历史诊断中的首轮正文未留存；此次只核对关系元数据，继续记录正文缺口。相关性检查采用保守的词项与原文引用验证，语义判断由原生复盘完成；其他领域可用通用机制，但方法有效性仍需要该领域的实际应用证据。

完整测试 home、数据库、请求记录和诊断日志保留在本地受控证据目录，提交材料仅包含必要摘要、合成模型产物和哈希。[证据索引](../evidence/INDEX.json)记录可提交文件的字节摘要；历史验收和生产学习数据保持原状。
