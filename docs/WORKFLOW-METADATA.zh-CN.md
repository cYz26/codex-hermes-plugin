# 全局流程学习（0.4.2）

全局配置可默认学习本机提取的固定流程信息；代码、文档和聊天正文继续经过资料准入。
固定流程投影不提供通用脱敏能力，也不建立完整的业务语义学习。

## 数据路径

`data_policy.workflow_projection: true` 为未通过正文准入的任务提供有限的学习路径。
采集入口只生成 `inspect/edit/test/execute/other` 动作类别和
`running/completed/failed/interrupted/unknown` 状态。标准测试命令只在简单命令结构下识别；
不执行命令来分类，不解释自由文本输出中的“成功”。原提示词、工具参数、工具输出和助手正文不入库。
聊天归属、工具 ID、宿主提供的 transcript 路径作为本地关联元数据保留。

终态回合转换成最多 128 个步骤的固定结构。原项目、聊天和回合标识不进入复盘正文；
原生观察接口使用固定的流程作用域及派生标识，本地另存实际归属。
针对 Codex 0.167，只从已验证身份的当前回合 transcript 补齐已有工具的退出状态，关闭任务正文提取。
未知结果保持未知；回合结束不等于业务正确。

Hermes 仍使用当前 provider、模型与原生 review，同一个 worker 串行执行。
流程复盘使用固定提示词，排除原生记忆、外部记忆 provider 和完整技能目录；
提示词重建也保留这一边界。工具检查只允许读取自己产生的 `workflow-*` 技能，
或用原生 `skill_manage(operations=[...])` 创建、修订这些技能的正文。
禁止任意文件读取、Memory 操作、命令执行、其他技能访问及资源文件写入。

流程技能仍经过来源、路径、凭据、私有标识和内容 hash 的共享检查。
“来自受限流程复盘”提供其资料来源依据，不会给普通业务技能放宽共享准入。
这一依据绑定实际写入后的内容版本与原生复盘回执；Curator 或其他写入者修改了内容后，
不能继承旧版本的依据。未验证的新版被拒绝，上一已发布版本继续可用。
没有足够经验时允许不写入；失败→编辑→通过的顺序不能证明因果或测试覆盖充分。

## 配置与回退

新建全局配置默认包含：

```json
{
  "capture_scope": "global",
  "checked_publication": true,
  "data_policy": {"enabled": true, "workflow_projection": true}
}
```

已有配置需显式增加该布尔值，保留 `assessment_command` 和验收范围。
设置为 `false` 可停止接收新的流程证据，未准入正文仍被拒绝。
`doctor` 分别报告流程投影、评估程序配置和正文边界。
更换插件包按 Codex 原生机制检查 hooks 信任，不能将旧指纹信任当作新包的授权。
升级启动失败时，流程技能凭证与原生技能一起恢复，保持内容版本对应；已交付回执保留当前状态。

## 验证

外围测试覆盖正文丢弃、未知状态、原标识不进入观察载荷、原生批量参数、
私有读取与可执行资源拒绝，以及提示词重建隔离。
`probes/workflow_learning.py` 在新合成 home 中预置私有记忆和技能标记，
用当前路由运行真实复盘，在 `pre_api_request` 检查实际请求是否带入标记。
它分别记录模型隔离、原记忆是否保持和技能是否变化；这不是 Desktop hooks 验收。

升级门禁另有修复：文件改名或大差异只进入 `mechanism_review_required`，
明确的 `plan_required` 不再触发自动适配。测试分别覆盖研究→验证→排队和重设计停止。
