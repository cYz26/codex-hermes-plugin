# 完整复用原生学习与维护（0.9.0）

2026-11-14 实施策略更新：后续以[原生优先优化方案](./NATIVE-FIRST-OPTIMIZATION.zh-CN.md)为准。
当前保留生产开关，语义合并、质量执行、语义准入和留存逐项完成隔离验证后再调整；
下文 2026-11-11 的启用目标是历史方案，不代表这些开关当前已开启。

本次范围来自 2026-11-11 用户要求：结合官方方案完善五项缺口，并完整复用 Hermes 原生自进化能力。目标是接通原生能力与 Codex 的来源、发布和读取流程。原生模型、复盘提示词、触发阈值、Curator 整理提示、记忆审批、技能锁、归档和恢复规则保持原样。

## 能力对应

| 能力 | 原生责任 | 插件适配 |
| --- | --- | --- |
| 自动复盘与显式学习 | review fork、Memory／Skills 工具、预算、写入保护 | 保留外部执行证据与项目范围，不建立第二个总结模型 |
| 记忆纠正 | patch/remove 待审、条目校验、原子批次 | 现有项目待审入口继续工作，不自动批准历史提案 |
| 周期整理 | 到期、空闲、固定保留、语义合并、备份与报告 | 等待完整原生整理结束，再发布或退出；idle_flush 只请求回合复盘 |
| 合并与恢复 | skill_manage、absorbed_into、归档、restore、账本 | 同步来源和旧名称；候选失败保留旧发布，成功后转发；恢复时还原归属 |
| 历史与留存 | 账本压缩、内容去重、回退、备份轮换 | 为新增的交付快照补引用保护和清理，不清理原生归档或另造账本 |
| 关联与召回 | related_skills、状态、使用记录 | 在来源和发布边界内推荐直接匹配及原生相关技能，最多五项 |
| 应用反馈 | 原生 view/use/patch 记录 | 保留版本绑定的交付、采用和测试证据，不将计数换算为学习收益 |

没有新增语义冲突裁判、向量数据库或自定义 Curator 提示词。原生模型负责提炼和整合；项目及企业范围、来源缺失和版本检查约束传播。USER.md 与外部 MemoryProvider 仍遵循原有项目归属和部署策略。

## 调度与来源

Learning API 内部适配复用官方到期检查、空闲阈值、运行占用检查和 `run_curator_review(synchronous=True)`，保留整理前备份、受保护技能、工具写入、报告及指标，不修改配置绕过到期条件。

宿主已 Stop／Interrupt 但工具结果仍未知的历史回合保留 incomplete 证据状态，不据此永久阻塞维护。空闲时长同时受真实宿主最近活动和原生观察活动限制；仍在运行的宿主回合继续阻止维护。

新增 `skill_lifecycle` capability 从原生账本提供有界分页。消费游标、来源、归档来源和别名在同一桥接事务内提交。只接受原生工具确认归档的 `absorbed_into` 声明，不从模型总结猜测合并关系。来源未知、企业范围冲突或游标失效时明确报告缺口，不凭目录扫描补造归属。

不归档的原生修订／新建也可能参考其他技能，因此将本次已准入输入库作为保守来源范围，明确标记其依据，不声称每个输入都被实际引用。进程中断后无法确认的改写保持待核实。原生整库回退没有逐项 restore 事件时，只对内容版本与已保存归档记录完全匹配的技能恢复归属。

官方 Curator 不需要学习插件专有的 `learning_scope` 字段。若全部输入版本均已通过共享发布，其产物可继承“通用候选”意图，绑定实际输出版本后继续通过完整的来源、内容和质量检查。显式项目范围不会被覆盖，也不会直接继承发布通过或脚本验证结果。

语义整理读取原生技能库，执行前用既有正文准入核对内容和来源。企业绑定失效时不调用整理模型。新版本重新经过发布与质量检查，不继承旧内容的验证凭证。原生修改仍不是跨文件事务，账本仍是尽力记录；缺失证据不构成已验证合并。

`learning_status` 增加 `native_curator` 和 `native_lifecycle`，分别显示原生开关、周期、上次执行与账本同步状态。服务可达和语义整理已经执行分别判断。

## 交付快照留存

每日留存沿用既有时机，新增原生 `prune_artifacts` 只处理 `learning/artifacts`：

- 保护当前原生技能包、当前发布、读取缓存，以及每项技能最近两个历史发布版。
- 最近退役版本至少保留 30 天，覆盖无状态读取回执；旧版本没有退役时间时先取得完整宽限期。
- 已记录的交付和应用证据引用继续保护，可能长期保留。
- 只删除超过 30 天、无引用且摘要匹配的完整快照。符号链接、非法名称、内容不一致和 staging 不作为孤儿快照删除。
- 预览不修改数据，每轮最多清理 100 份，由原生所有者执行。原生 archive、账本及 blobs 继续遵守官方策略。

## 原生开关与兼容

完整适配面向 v0.23.0／v0.23.1 的 Learning API 补丁。历史 v0.22.7 基线与验收保留原样；缺少新 capability 的运行时不宣称支持完整维护。

升级代码本身保留既有配置。启用语义整理使用原生 `curator.enabled=true`、`curator.consolidate=true`，其他时间、阈值和提示词保持原值。用户本次已经明确要求完整复用，部署在候选验证后启用这两个目标项，并核对同一企业部署的配置绑定；不能用重绑恢复已撤销授权。

`scripts/bridge curator-config --settings /ABS/bridge.json` 预览这两个目标项；加 `--apply` 后排队，由唯一学习写入者调用原生配置入口。`learning_status.native_curator_configuration` 确认实际结果。保留目标项的恢复记录；企业绑定失效时拒绝启用，配置中断恢复也只接受同一授权记录与未改变的其他配置。

整理在原生到期／空闲条件满足后执行，不增加另一个定时模型进程。每日／每周人工审查仍是独立的质量观察方案。

## 验证与恢复

`probes/native_lifecycle.py` 在全新临时 home 使用真正的 Curator、skill_manage、账本、备份与恢复，通过脚本化决策验证合并→候选拒绝→旧版可读→新发布→别名／资源／召回→恢复归属。它不代表真实模型质量或 App 界面验收。

`tests/test_lifecycle.py` 覆盖来源、范围、游标缺口、关联推荐和引用保护；原生 `tests/agent/test_learning_lifecycle.py` 覆盖调度完成、账本分页与快照清理。新用例加入候选验证，并保留已有原生回归。结果以本次执行记录为准。

桥接状态为附加 meta 条目，没有改 journal schema 或重写知识。回退保留当前知识、事件箱和企业授权；已合并技能可通过原生恢复入口恢复，不能用旧数据库覆盖新知识。
